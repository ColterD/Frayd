## Library administration and scan lifecycle

Before these changes, long scan/probe work could monopolize the application database mutex, scan refusal could appear as completion, and overlapping asynchronous UI results could publish stale state. Scans now use a separate WAL database connection and a single compare-and-set worker owner with scope-bound release on failure/unwind. Proxy-facing health, static, library and progress reads have explicit before/during/after blocked-probe checks.

One ordered effective root array is shared by scanner, ingestion and cache validation. Nonempty `FRAYD_LIBRARY` selects one exclusive root and locks root edits; otherwise database `library_paths` is authoritative, with legacy `library_path` fallback only when the array is absent. Explicit `[]` disables the library. Existing roots canonicalize/deduplicate in order. A removed or temporarily unavailable configured root does not erase indexed IDs, progress, annotations or source bytes; startup does not recreate missing media roots. New invalid roots are refused.

Settings validate the entire request before an atomic transaction. Environment locks and active scan/conversion/ingestion work return 409; database failures do not publish partial settings. Media removal refuses referenced or conversion-owned media and never grants source-file deletion authority. User cleanup is account-specific and transactional, retains last-admin protections and rolls back child deletion on failure. Null permissions clear a restriction; malformed changes fail without partial updates.

The client keeps complete library snapshots separate from kind/search views, retains sorting/navigation intent, and rejects stale search/render/continue/toolbar/account responses. Settings and dashboard scan observers retry transient status transport failures, attach to an already-running scan after 409 and refresh the current account even after Settings closes. They never replay scan POST. Refused root/cache work exposes path-free `scan_error`, shows failure/retry instead of completion, and clears on successful scan/restart. Privacy assertions check both configured roots. Scanner diagnostics report unreadable walks/directories/entries while accessible siblings continue; permission tests require actual nonroot PermissionDenied.

## Source identity and reader caches

Changed sources refresh size/mtime without replacing media identity, user titles, progress or unrelated metadata. Comic page lists and page content share persisted order, including legacy unflagged UTF-8 archive characterization. Detectable replacement clears only comic `pages` or EPUB `spine` caches; lazy parsing runs outside the application mutex and guarded publication merges only the cache field if the captured source/database snapshot still matches. An optional database cache-write error can return the successfully parsed content; a zero-row stale publication remains refused. Missing/broken archives retain their failure behavior.

Known movie/episode replacements invalidate old playback and duration together. A fresh duration probe publishes only after an immediate transaction and current filesystem/database fingerprint checks; known-version probe failure leaves duration unknown. An incomplete legacy fingerprint can retain its unqualified duration on failure. Unchanged files are not automatically reprobed. Separately indexed genuine sources referenced by legacy conversion pointers remain eligible for refresh. Original source bytes stay outside generated-output deletion authority.

The replacement detector uses size plus seconds-granularity mtime. Replacements preserving both fields can escape detection; the guards do not make arbitrary filesystem writers atomic. Audio duration and general metadata refresh are not included in the replacement-duration correction.

## Conversion storage and recovery

Conversion previously wrote browser output beside originals and lacked sufficient provenance to distinguish genuine similarly named media. Output now lives in a separate writable cache, normally `/data/transcodes/<media-id>/<job-uuid>/audio.mp4`, with exact database ownership. Read-only library conversion is exercised with actual FFmpeg. Cache validation rejects symlinks, unsafe ancestors and overlap with any configured root; registry or namespace failures publish no output.

The additive `transcode_artifacts` table records path, owner media/source, temp/final role, generated/legacy-reference provenance and unknown/pending/completed/retiring lifecycle. Startup migration is idempotent and preserves unknown history. Indexes on `media(transcode_path)` and `transcode_artifacts(owner_media_id)` replace correlated table scans with indexed lookups in the 3,000-source query-plan fixture. Names and suffixes never prove ownership. Generated-row pruning preserves progress, annotations, tracks, playlists, competing ownership, legacy-only references and genuine source collisions.

A stable-media-ID reservation is checked under an SQLite immediate transaction before namespace creation, including after source-path changes. Retained unknown jobs always hold their reservation; pending/retiring jobs also hold when recovery is unqualified. Source filesystem/database versions must still match before completed output publishes. Failed or unpublished jobs retire only their own unreferenced pair. A known replaced source can retire its qualified prior completed pair. Linux lease/process checks reclaim proven inactive jobs after interruption/timeout while active converters, uncertain history and unrelated files remain held. Repeated scans cannot create unbounded new namespaces for the same retained reservation. This is not a general orphan reaper or a global cache-size bound; unqualified hosts retain conservative reservations.
